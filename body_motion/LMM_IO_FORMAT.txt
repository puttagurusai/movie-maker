================================================================================
  LMM_IO_FORMAT.txt
  Input / Output contract for general LMM ↔ projface_v1 pipeline
================================================================================

  Training is done SEPARATELY (Colab / Kaggle / your code).
  This file only defines what our pipeline SENDS and what it EXPECTS BACK
  so any trained model can plug in via LmmEngine.

  Related:
    body_motion/FINAL_BONE_MAP.json   Blender bone names
    body_motion/catalog.json          clip engine (not LMM)
    blender_receiver.py               body playback
    face_agents/motion_controller.py  MotionPlan routing


================================================================================
1. PIPELINE FLOW (I/O only)
================================================================================

  [Director / text / intent]
          |
          v
  Text→LMM controller  builds  >>> LMM_REQUEST (JSON) <<<
          |
          v
  Your trained model (external)  returns  >>> LMM_RESPONSE / MotionBuffer <<<
          |
          v
  Adapter  maps  →  SMPL-X_Armature pose (Blender)
          |
          v
  Face pipeline  (independent — never in LMM I/O)


================================================================================
2. INPUT TO LMM  —  LMM_REQUEST
================================================================================

  Format: JSON object (or equivalent Python dict).
  Produced by our Text→LMM controller; consumed by your infer code.


  2.1 Required fields
  -------------------

  {
    "prompt": "a person walks forward then waves",
    "frames": 90,
    "fps": 30,
    "seed": 42
  }

  prompt   string   Natural language motion description (English).
                    Primary control for general LMM.
                    May be free user text or a template from intent.

  frames   int      Number of output frames to generate.
                    Range recommended: 16 .. 196
                    Must match fps for duration: duration_s ≈ frames / fps

  fps      int      Always 30 for this pipeline (Blender receiver / clips).
                    If model was trained at 20 fps, YOU resample to 30
                    before returning LMM_RESPONSE.

  seed     int      RNG seed for reproducibility (≥ 0).


  2.2 Optional fields (controller may send; model may ignore)
  -------------------------------------------------------------

  {
    "cfg_scale": 5.0,
    "intensity": 0.85,
    "intent": "wave",
    "duration_s": 3.0,
    "locomotion": false,
    "upper_only": false,
    "hand": "right",
    "emotion": "happy",
    "request_id": "uuid-or-string"
  }

  cfg_scale     float   Classifier-free guidance scale (typical 2.5 .. 7.5).
  intensity     float   0.2 .. 1.2  motion amplitude hint (post-scale allowed).
  intent        string  Catalog-style id if known (wave, walk, …) or "custom".
                        For logging / routing; prompt remains authoritative.
  duration_s    float   If set and frames omitted, frames = round(duration_s * fps).
  locomotion    bool    Hint: allow root translation (true) vs plant (false).
  upper_only    bool    Hint: prefer upper-body motion (legs may still be returned;
                        pipeline may blend later). Model may ignore in V1.
  hand          string  "left" | "right" | "both" | "none"  (hint only).
  emotion       string  Optional adjective already baked into prompt often.
  request_id    string  Echo back in response for async jobs.


  2.3 What is NOT input to LMM
  ----------------------------
  - Face blendshapes / ARKit keys
  - Audio waveform / visemes
  - Full bone Euler lists from the LLM director
  - Mesh geometry / betas (shape) for V1 product path


  2.4 Minimal valid example
  -------------------------

  {
    "prompt": "a person waves with the right hand",
    "frames": 60,
    "fps": 30,
    "seed": 0
  }


================================================================================
3. OUTPUT FROM LMM  —  LMM_RESPONSE (MotionBuffer)
================================================================================

  Format: JSON metadata + numeric arrays.
  Preferred delivery for files: one .npz (or .npy + json sidecar).
  Preferred in-process: Python dict with numpy arrays.


  3.1 Required fields
  -------------------

  {
    "schema_version": 1,
    "fps": 30,
    "frames": 60,
    "joint_format": "smplx_axis_angle",
    "joints": { ... },
    "root": { ... },
    "meta": { ... }
  }

  Detailed numeric layout below.


  3.2 joint_format  (pick ONE; declare it; adapter handles conversion)
  --------------------------------------------------------------------

  Supported values for this pipeline:

  A) "smplx_axis_angle"     *** preferred if you train SMPL-X params ***
  B) "smpl_axis_angle"      SMPL axis-angle body
  C) "blender_quat_wxyz"    if you already output our bone quats
  D) "humanml3d_joints22"   *** preferred if LMM is trained on official
                            HumanML3D new_joints (T,22,3) positions ***
  E) "humanml3d_feature"    new_joint_vecs (T,D) + must ship Mean/Std
                            and recover path (harder for Blender)

  Declare exactly one in the response.

  Official HumanML3D on-disk layout (train data, not the response file):
    new_joint_vecs/*.npy  Mean.npy Std.npy
    new_joints/*.npy      (T, 22, 3)
    texts/*.txt
    train.txt val.txt test.txt
  See body_motion/LMM(learned motion model).txt §1


  ----------------------------------------------------------------------------
  3.3 Format A — smplx_axis_angle  (preferred)
  ----------------------------------------------------------------------------

  body_pose:   float32 array  shape (T, 21, 3)
               SMPL-X body joints axis-angle (exclude jaw, eyes, hands optional)

  global_orient: float32 (T, 3)   root orientation axis-angle

  transl:      float32 (T, 3)     root translation (meters)
               If locomotion=false was requested, may be near zero / relative

  left_hand_pose:  optional float32 (T, 15, 3)  or (T, 45)
  right_hand_pose: optional float32 (T, 15, 3)  or (T, 45)
               If omitted, pipeline leaves fingers at rest.

  expression / jaw:  MUST BE OMITTED or ignored by pipeline (face owns mouth)

  Units: meters, axis-angle radians, Y-up or Z-up must be stated in meta.up_axis


  ----------------------------------------------------------------------------
  3.4 Format B — smpl_axis_angle
  ----------------------------------------------------------------------------

  body_pose:     float32 (T, 23, 3) or (T, 69)  per your SMPL convention
  global_orient: float32 (T, 3)
  transl:        float32 (T, 3)

  No face. Hands usually absent.
  Adapter maps SMPL body → closest SMPL-X_Armature bones.


  ----------------------------------------------------------------------------
  3.4b Format D — humanml3d_joints22  (from official new_joints)
  ----------------------------------------------------------------------------

  joints:  float32 array  shape (T, 22, 3)
           3D joint positions, HumanML3D / SMPL 22-joint skeleton
  fps: 30 after resample
  meta.n_joints: 22
  meta.units: "m"
  meta.up_axis: "y"  (or as in your export)

  Pipeline adapter: positions → bone rotations on SMPL-X_Armature
  (IK / retarget). Do not include face joints.


  ----------------------------------------------------------------------------
  3.5 Format C — blender_quat_wxyz  (direct armature apply)
  ----------------------------------------------------------------------------

  joint_names:  list[str] length J
                MUST use our Blender names (subset of FINAL_BONE_MAP targets):

    pelvis, spine1, spine2, spine3, neck, head,
    left_collar, left_shoulder, left_elbow, left_wrist,
    right_collar, right_shoulder, right_elbow, right_wrist,
    left_hip, left_knee, left_ankle, left_foot,
    right_hip, right_knee, right_ankle, right_foot,
    left_thumb1, left_thumb2, left_thumb3,
    left_index1, left_index2, left_index3,
    left_middle1, left_middle2, left_middle3,
    left_ring1, left_ring2, left_ring3,
    left_pinky1, left_pinky2, left_pinky3,
    right_thumb1, right_thumb2, right_thumb3,
    right_index1, right_index2, right_index3,
    right_middle1, right_middle2, right_middle3,
    right_ring1, right_ring2, right_ring3,
    right_pinky1, right_pinky2, right_pinky3

  rotations:  float32 (T, J, 4)   quaternion (w, x, y, z) per joint
              LOCAL pose space (same as Blender pose bone local quat)

  root_location: float32 (T, 3)   applied to pelvis location
                 meters in armature/object space

  Do NOT include: jaw, left_eye_smplhf, right_eye_smplhf


  ----------------------------------------------------------------------------
  3.6 meta (required block)
  ----------------------------------------------------------------------------

  "meta": {
    "schema_version": 1,
    "prompt": "echo of input prompt",
    "seed": 42,
    "request_id": "optional echo",
    "model_name": "your-checkpoint-id",
    "joint_format": "smplx_axis_angle",
    "up_axis": "y",
    "fps_native": 30,
    "units": "m"
  }


  3.7 .npz file layout (file exchange)
  -------------------------------------

  File:  lmm_out_<request_id>.npz

  Keys:
    fps              int / float
    frames           int
    joint_format     str
    # depending on joint_format:
    body_pose        float32
    global_orient    float32
    transl           float32
    left_hand_pose   float32 (optional)
    right_hand_pose  float32 (optional)
    # OR for blender_quat_wxyz:
    joint_names      array of unicode strings
    rotations        float32 (T,J,4)
    root_location    float32 (T,3)
    # always:
    prompt           str
    seed             int
    model_name       str
    up_axis          str
    schema_version   int == 1


  3.8 Error response
  ------------------

  {
    "ok": false,
    "error": "human readable message",
    "request_id": "..."
  }

  Pipeline must fallback to clip engine (idle / talk_open).


  3.9 Success flag (optional)
  ---------------------------

  {
    "ok": true,
    ... all required motion fields ...
  }


================================================================================
4. CONSTRAINTS (pipeline will assume these)
================================================================================

  fps_out                 == 30   (resample before return if needed)
  frames                  == request.frames  (or document truncation)
  No NaN / Inf
  Quaternion norms        ≈ 1 if format C
  Time order              frame 0 .. T-1 chronological
  Face / jaw / shape keys never in payload
  schema_version          == 1


================================================================================
5. WHO DOES WHAT
================================================================================

  YOU (separate train / infer service)
    - Accept LMM_REQUEST
    - Run model
    - Return LMM_RESPONSE in format A, B, or C at 30 fps

  OUR PIPELINE (complete path)
    - Build LMM_REQUEST from text / intent
    - Call LMM infer → lmm_out.npz (this format)
    - ADAPTER (fills the gap for joints22):
        tools/apply_lmm_npz_to_smplx.py
        → humanml3d_joints22 (T,22,3)
        → pose keys on SMPL-X_Armature Action
    - Formats A/B/C may map more directly; D (joints22) REQUIRES the adapter
    - blender_receiver can play the resulting Action like any clip
    - Face stays on viseme/emotion path
    - On error → clip_catalog fallback

  Adapter command (Blender):
    blender.exe whole_body_retargeted.blend --python tools/apply_lmm_npz_to_smplx.py -- ^
      --npz "lmm train/lmm_out.npz" --action lmm_walk --out body_motion/_lmm_applied.blend
