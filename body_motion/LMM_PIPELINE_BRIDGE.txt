================================================================================
  LMM → projface pipeline bridge (how the "adapter gap" is filled)
================================================================================

  You were right: training was specified to FIT the pipeline. That means the
  EXPORT FORMAT is fixed. Applying it onto SMPL-X_Armature is a separate,
  explicit step (adapter) — same idea as FBX → retarget → Action for Mixamo.

================================================================================
1. END-TO-END CHAIN
================================================================================

  [1] TRAIN (Colab / Kaggle)
        HumanML3D + Learned Motion Matching
        → checkpoints

  [2] INFER
        prompt "a man is walking"
        → lmm_out.npz
            joint_format = humanml3d_joints22
            joints       = (T, 22, 3) float32 @ fps=30

  [3] ADAPTER  ← THIS WAS THE MISSING PRODUCT STEP (now provided)
        tools/apply_lmm_npz_to_smplx.py
        → reads npz
        → maps HML 22 joints → SMPL-X_Armature body bones
        → writes Blender Action (rotation_quaternion + pelvis location)
        → fingers/jaw left at rest (face pipeline owns mouth)

  [4] RUNTIME
        blender_receiver / Action Editor plays that Action
        like idle/walk clips from catalog
        Face agents still drive shape keys only

================================================================================
2. WHY AN ADAPTER IS REQUIRED (not a contradiction)
================================================================================

  Training target was chosen for HumanML3D:

    new_joints (T,22,3) positions  — what LMM Decompressor outputs

  Blender character needs:

    SMPL-X_Armature pose bone LOCAL ROTATIONS (+ root location)

  Positions ≠ bone local quats. Conversion = adapter.

  This is the same class of step as:
    Mixamo FBX → FINAL_BONE_MAP retarget → Action
  which you already did for clips.

  LMM train guide focused on (1)+(2). Product wiring needs (3).
  Format contract was always LMM_IO_FORMAT; adapter implements format D.
